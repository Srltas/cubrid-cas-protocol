SCHEMA_INFO

스키마 타입에 따라 스키마 정보를 조회하고 그 결과를 가져올 스키마 정보 핸들을 만든다

항목내용
함수 코드9
엔진 이름CAS_FC_SCHEMA_INFO
JDBC 이름GET_SCHEMA_INFO
대조한 커밋엔진 e30370dc03, JDBC 18d5254624 (2026-11-16)

요청​

순서필드형식크기조건설명
1schema_typeARG_INT8조회할 스키마 정보의 종류다. CAS는 이 값으로 응답을 쓰는 함수를 고르고 결과의 컬럼 목록도 이 값으로 정해진다. 값: 스키마 타입
2arg1ARG_STRING4 + n대상의 이름이나 패턴이고 스키마 타입마다 뜻이 다르다. 길이가 0이면 CAS는 이 인자가 없는 것(NULL)으로 다룬다
3arg2ARG_STRING4 + n둘째 이름이나 패턴이고 사용하는 스키마 타입은 비고에 적었다. 길이가 0이면 CAS는 이 인자가 없는 것(NULL)으로 다룬다
4flagARG_BYTE5arg1이나 arg2를 패턴으로 비교할지 정하는 비트다. 어느 비트를 보는지는 스키마 타입마다 다르고 비고에 적었다. 플래그: 스키마 정보의 패턴 플래그
5shard_idARG_INT8CAS는 읽기만 하고 사용하지 않는다

응답​

결과 코드: 성공하면 새로 만든 스키마 정보 핸들의 번호

순서필드형식크기조건설명
1result_meta묶음가변스키마 타입 ATTR_WITH_SYNONYM에서 동의어를 찾는 질의가 실패해 CAS가 결과 코드만 쓰는 경우가 아닐 때
1.1tuple_countINT4결과가 가진 행의 전체 수다. 행은 이 핸들로 FETCH를 보내 가져온다
1.2num_columnINT4결과의 컬럼 수다. 스키마 타입마다 정해진 값이다
1.3columnscolumn_info × num_column가변결과의 컬럼마다의 정보다. 스키마 타입마다 정해져 있고 그 목록은 참조 표 스키마 타입의 스키마 타입별 결과 컬럼 절에 있다
1.3.1cas_net_first_byteBYTE10x80은 타입을 2바이트로 보낸다는 표시다. 0x60 자리는 컬렉션 구분 코드이고, 아래 3비트는 문자셋 번호다
1.3.2cas_net_second_byteBYTE1타입 코드. 컬렉션이면 원소의 타입 코드다. 값: 타입 코드
1.3.3scaleSHORT2컬럼의 scale이다
1.3.4precINT4컬럼의 precision이다
1.3.5nameSTRING4 + nJDBC는 이 컬럼의 문자셋이 아니라 연결의 문자셋으로 읽는다

비고​

  • 인자가 4개보다 적으면 CAS는 CAS_ER_ARGS 오류로 응답한다. CAS는 인자 수를 4개까지만 검사하고 다섯째 인자인 shard_id를 읽는다. 여섯 번째부터는 읽지 않는다.
  • CAS는 먼저 서버 핸들을 만든다. 핸들 수가 브로커 파라미터 MAX_PREPARED_STMT_COUNT에 이르렀으면 CAS_ER_MAX_PREPARED_STMT_COUNT_EXCEEDED 오류로, 메모리가 모자라면 CAS_ER_NO_MORE_MEMORY 오류로 응답한다.
  • schema_type이 1부터 21까지의 값이 아니면 CAS는 CAS_ER_SCHEMA_TYPE 오류로 응답한다. CAS는 오류로 응답할 때 만들어 둔 핸들을 해제한다.
  • 스키마 타입 CLASS, VCLASS, QUERY_SPEC, ATTRIBUTE, CLASS_ATTRIBUTE, DIRECT_SUPER_CLASS, PRIMARY_KEY, ATTR_WITH_SYNONYM, SCHEMAS에서 CAS는 arg1과 arg2를 문자열 리터럴 자리에 넣어 만든 SELECT 문을 실행해 결과를 얻는다. CAS는 arg1과 arg2에 든 작은따옴표를 바꾸지 않고 그대로 넣는다. 그 문을 열거나 컴파일하지 못하면 DBMS_ERROR_INDICATOR와 엔진의 오류 번호로 응답한다. 실행하지 못하면 DBMS_ERROR_INDICATOR로 응답하되 오류 코드 자리에는 엔진의 오류 번호가 아니라 컴파일한 문장의 번호(stmt_id)를 싣는다. CAS는 세션마다 문장을 하나만 컴파일하므로 이 값은 1이다. 오류 메시지는 엔진의 오류 메시지다.
  • 스키마 타입 ATTR_WITH_SYNONYM(20)에서 CAS는 속성을 찾기 전에 동의어를 찾는 질의를 실행하는데, 이 질의가 실패하면 오류로 응답하지 않고 결과 코드만 쓴다. 이때는 result_meta가 오지 않는다. 질의를 열거나 컴파일하지 못했을 때와 엔진 함수 db_query_first_tuple이 DB_CURSOR_END(1)를 돌려줬을 때는 핸들을 남겨 둔다. 질의를 실행하지 못했을 때, db_query_first_tuple이 음수(DB_CURSOR_ERROR(-1)나 엔진의 오류 번호)를 돌려줬을 때, 첫 행의 값을 읽지 못했을 때는 CAS가 오류 정보를 채우지 않은 채 오류 경로로 가서 핸들을 해제하므로 응답의 결과 코드는 이미 해제한 핸들의 번호다.
  • 스키마 타입 CLASS, VCLASS, QUERY_SPEC, ATTRIBUTE, CLASS_ATTRIBUTE, DIRECT_SUPER_CLASS, PRIMARY_KEY, ATTR_WITH_SYNONYM에서 CAS는 arg1을 소문자로 바꾼 뒤 첫 점에서 나눈다. 점 앞의 길이가 1 이상 DB_MAX_SCHEMA_LENGTH(32) 미만이면 점 앞을 소유자 이름으로, 점 뒤를 클래스 이름으로 사용하고 소유자 이름은 대문자로 바꿔 비교한다. 그렇지 않으면 arg1 전체가 클래스 이름이고 소유자를 가리지 않는다. ATTR_WITH_SYNONYM에서는 이 이름이 동의어 이름이고, 소유자 이름이 없으면 데이터베이스에 접속한 사용자 이름을 소유자로 사용한다. ATTRIBUTE, CLASS_ATTRIBUTE, ATTR_WITH_SYNONYM에서는 arg2도 소문자로 바꾼다. 이 스키마 타입들과 SCHEMAS에서 패턴은 SQL의 LIKE로 비교하고 이스케이프 문자는 역슬래시다.
  • 스키마 타입 TRIGGER의 arg1, flag의 CCI_CLASS_NAME_PATTERN_MATCH(1) 비트가 켜진 CLASS_PRIVILEGE의 arg1, ATTR_PRIVILEGE의 arg2는 CAS가 이름을 직접 비교한다. 패턴으로 비교할 때는 %와 _가 와일드카드이고 이스케이프 문자는 역슬래시이며 대소문자를 가리지 않는다. 패턴이 아닐 때 CAS가 직접 비교하는 TRIGGER의 arg1과 ATTR_PRIVILEGE의 arg2는 대소문자까지 같아야 한다. 비트가 꺼진 CLASS_PRIVILEGE의 arg1과 ATTR_PRIVILEGE의 arg1은 CAS가 비교하지 않고 엔진 함수 db_find_class에 그대로 넘겨 클래스를 찾는다. CAS는 이 스키마 타입들에서 arg1과 arg2를 소문자로 바꾸지 않는다.
  • arg2는 스키마 타입 ATTRIBUTE, CLASS_ATTRIBUTE, ATTR_PRIVILEGE, CROSS_REFERENCE, ATTR_WITH_SYNONYM에서만 사용한다. flag의 CCI_CLASS_NAME_PATTERN_MATCH(1) 비트는 CLASS, VCLASS, ATTRIBUTE, CLASS_ATTRIBUTE, TRIGGER, CLASS_PRIVILEGE, DIRECT_SUPER_CLASS, SCHEMAS에서만, CCI_ATTR_NAME_PATTERN_MATCH(2) 비트는 ATTRIBUTE, CLASS_ATTRIBUTE, ATTR_PRIVILEGE, ATTR_WITH_SYNONYM에서만 사용한다.
  • 스키마 타입 CLASS(1)와 VCLASS(2)에서 arg1은 클래스 이름이다. flag의 CCI_CLASS_NAME_PATTERN_MATCH(1) 비트가 켜져 있으면 arg1을 패턴으로 비교하고 arg1이 없으면 이름을 가리지 않는다. 꺼져 있으면 이름이 같은 클래스만 찾고 arg1이 없으면 빈 이름으로 찾는다. VCLASS는 가상 클래스만 찾고 CLASS는 클래스의 종류를 가리지 않는다. arg2와 flag의 다른 비트는 사용하지 않는다.
  • 스키마 타입 QUERY_SPEC(3)에서 arg1은 가상 클래스 이름이고 CAS는 이름이 같은 가상 클래스만 찾는다. arg1이 없으면 빈 이름으로 찾는다. arg2와 flag는 사용하지 않는다.
  • 스키마 타입 ATTRIBUTE(4)와 CLASS_ATTRIBUTE(5)에서 arg1은 클래스 이름이고 arg2는 속성 이름이다. flag의 CCI_CLASS_NAME_PATTERN_MATCH(1) 비트는 arg1을, CCI_ATTR_NAME_PATTERN_MATCH(2) 비트는 arg2를 패턴으로 비교할지 정한다. 비트가 켜져 있고 그 인자가 없으면 그 이름을 가리지 않고, 꺼져 있고 그 인자가 없으면 빈 이름으로 찾는다. ATTRIBUTE는 인스턴스 속성과 공유 속성을, CLASS_ATTRIBUTE는 클래스 속성을 찾는다.
  • 스키마 타입 METHOD(6), CLASS_METHOD(7), METHOD_FILE(8), SUPERCLASS(9), SUBCLASS(10), CONSTRAINT(11)에서 arg1은 클래스 이름이고 CAS는 arg1을 바꾸지 않고 엔진 함수 db_find_class에 넘겨 클래스를 찾는다. arg1이 없거나 클래스를 찾지 못하면 행이 0인 결과로 응답한다. METHOD는 엔진 함수 db_get_methods가, CLASS_METHOD는 db_get_class_methods가 돌려주는 메서드 목록이고, SUPERCLASS는 db_get_superclasses가, SUBCLASS는 db_get_subclasses가 돌려주는 클래스 목록이다. METHOD, CLASS_METHOD, METHOD_FILE, CONSTRAINT에서는 엔진 함수가 실패해도 CAS는 오류로 응답하지 않고 행이 0인 결과로 응답한다. SUPERCLASS와 SUBCLASS에서 목록에 든 클래스의 종류를 알아내지 못하면 CAS는 DBMS 오류로 응답한다. arg2와 flag는 사용하지 않는다.
  • 스키마 타입 TRIGGER(12)에서 arg1은 트리거의 대상 클래스 이름이다. flag의 CCI_CLASS_NAME_PATTERN_MATCH(1) 비트가 켜져 있으면 arg1을 패턴으로 비교하고 arg1이 없으면 엔진 함수 db_find_all_triggers가 돌려주는 트리거를 모두 찾는다. 꺼져 있으면 대상 클래스의 이름이 같은 트리거만 찾고 arg1이 없으면 행이 0인 결과로 응답한다. arg1의 첫 점 앞이 길이 1 이상 DB_MAX_SCHEMA_LENGTH(32) 미만이고 데이터베이스에 있는 사용자 이름이면 CAS는 그 사용자가 소유한 트리거만 남기고 대상 클래스 이름의 첫 점 뒤를 arg1의 점 뒤와 비교한다. 그렇지 않으면 대상 클래스의 이름 전체를 arg1 전체와 비교한다. 트리거를 찾는 도중에 엔진 오류가 나면 CAS는 오류로 응답하지 않고 행이 0인 결과로 응답한다. arg2와 flag의 다른 비트는 사용하지 않는다.
  • 스키마 타입 CLASS_PRIVILEGE(13)에서 arg1은 클래스 이름이다. flag의 CCI_CLASS_NAME_PATTERN_MATCH(1) 비트가 꺼져 있으면 CAS는 arg1을 바꾸지 않고 엔진 함수 db_find_class에 넘겨 클래스 하나를 찾고, arg1이 없거나 클래스를 찾지 못하면 행이 0인 결과로 응답한다. 켜져 있으면 모든 클래스의 이름을 arg1과 패턴으로 비교하고 arg1이 없으면 이름을 가리지 않는다. 이때 arg1의 첫 점 앞이 길이 1 이상 DB_MAX_SCHEMA_LENGTH(32) 미만이고 데이터베이스에 있는 사용자 이름이면, 시스템 클래스가 아닌 클래스는 그 사용자가 소유한 것만 남기고 이름의 첫 점 뒤를 arg1의 점 뒤와 비교하며, 시스템 클래스는 소유자를 가리지 않고 이름 전체를 arg1의 점 뒤와 비교한다. 그렇지 않으면 모든 클래스의 이름 전체를 arg1 전체와 비교한다. arg2와 flag의 다른 비트는 사용하지 않는다.
  • 스키마 타입 ATTR_PRIVILEGE(14)에서 arg1은 클래스 이름이고 arg2는 속성 이름이다. CAS는 arg1을 바꾸지 않고 엔진 함수 db_find_class에 넘겨 클래스를 찾으며 flag의 CCI_CLASS_NAME_PATTERN_MATCH(1) 비트는 사용하지 않는다. arg1이 없거나 클래스를 찾지 못하거나 그 클래스의 권한을 얻지 못하면 행이 0인 결과로 응답한다. CCI_ATTR_NAME_PATTERN_MATCH(2) 비트가 켜져 있으면 arg2를 패턴으로 비교하고 arg2가 없으면 엔진 함수 db_get_attributes가 돌려주는 속성을 모두 찾는다. 꺼져 있으면 이름이 같은 속성만 찾고 arg2가 없으면 행이 0인 결과로 응답한다.
  • 스키마 타입 DIRECT_SUPER_CLASS(15)에서 arg1은 클래스 이름이다. flag의 CCI_CLASS_NAME_PATTERN_MATCH(1) 비트가 켜져 있으면 arg1을 패턴으로 비교하고 arg1이 없으면 이름을 가리지 않는다. 꺼져 있으면 이름이 같은 클래스만 찾고 arg1이 없으면 빈 이름으로 찾는다. arg2와 flag의 다른 비트는 사용하지 않는다.
  • 스키마 타입 PRIMARY_KEY(16)에서 arg1은 클래스 이름이다. CAS는 소문자로 바꾼 arg1 전체를 엔진 함수 db_find_class에 넘겨 클래스를 찾는다. arg1이 없거나 클래스를 찾지 못하면 행이 0인 결과로 응답하고, 찾으면 이름이 같은 클래스의 기본 키를 SELECT 문으로 찾는다. arg2와 flag는 사용하지 않는다.
  • 스키마 타입 IMPORTED_KEYS(17)에서 arg1은 외래 키를 가진 클래스의 이름이고, EXPORTED_KEYS(18)에서 arg1은 기본 키를 가진 클래스의 이름이다. CROSS_REFERENCE(19)에서 arg1은 기본 키를 가진 클래스의 이름이고 arg2는 외래 키를 가진 클래스의 이름이다. CAS는 이름을 바꾸지 않고 엔진 함수 db_find_class에 넘겨 클래스를 찾고, 찾지 못하면 행이 0인 결과로 응답한다. EXPORTED_KEYS와 CROSS_REFERENCE에서는 arg1의 클래스에 기본 키가 없어도 행이 0인 결과로 응답한다. 세 스키마 타입 모두 flag를 사용하지 않고 IMPORTED_KEYS와 EXPORTED_KEYS는 arg2도 사용하지 않는다.
  • 스키마 타입 IMPORTED_KEYS(17), EXPORTED_KEYS(18), CROSS_REFERENCE(19)에서 arg1이 없으면 CAS는 CAS_ER_ARGS 오류로 응답한다. CROSS_REFERENCE에서는 arg1의 클래스를 찾은 뒤에 arg2가 없으면 CAS_ER_ARGS 오류로 응답한다. IMPORTED_KEYS에서 외래 키가 참조하는 클래스에 기본 키가 없으면 ER_FK_REF_CLASS_HAS_NOT_PK, 세 스키마 타입에서 기본 키나 외래 키에 속성이 없으면 ER_SM_INVALID_CONSTRAINT, 기본 키와 외래 키의 속성 수가 다르면 ER_FK_NOT_MATCH_KEY_COUNT의 DBMS 오류로 응답한다. EXPORTED_KEYS와 CROSS_REFERENCE에서 기본 키를 참조한다고 기록된 클래스에 그 기본 키를 참조하는 외래 키가 없을 때도 ER_SM_INVALID_CONSTRAINT다. 그 밖에 참조 관계에 있는 클래스나 그 이름을 얻지 못하면 엔진의 오류 번호로 응답한다. IMPORTED_KEYS에서는 외래 키가 참조하는 클래스의 제약 조건을 얻은 뒤 엔진에 남아 있는 오류 번호가 0이 아니어도 그 오류 번호로 응답한다.
  • 스키마 타입 ATTR_WITH_SYNONYM(20)에서 arg1은 동의어 이름이고 arg2는 속성 이름이다. CAS는 arg1에 소유자 이름이 없으면 데이터베이스에 접속한 사용자 이름을 소유자로 삼아 그 이름과 소유자의 동의어를 찾고, 동의어가 가리키는 대상 클래스의 인스턴스 속성과 공유 속성을 찾는다. arg1이 없거나 그런 동의어가 없으면 행이 0인 결과로 응답한다. 대상 클래스는 이름이 같은 것만 찾으므로 flag의 CCI_CLASS_NAME_PATTERN_MATCH(1) 비트는 사용하지 않는다. CCI_ATTR_NAME_PATTERN_MATCH(2) 비트가 켜져 있으면 arg2를 패턴으로 비교하고 arg2가 없으면 속성 이름을 가리지 않는다. 꺼져 있으면 이름이 같은 속성만 찾고 arg2가 없으면 빈 이름으로 찾는다. 동의어를 찾는 질의가 실패했을 때의 응답은 result_meta가 오지 않는 경우를 적은 앞의 항목에 적었다.
  • 스키마 타입 SCHEMAS(21)에서 arg1은 스키마 이름이다. CAS는 db_user의 사용자 이름과, db_auth에서 그 사용자들이 권한을 받은 대상의 소유자 이름을 찾고, arg1을 대문자로 바꿔 비교한다. flag의 CCI_CLASS_NAME_PATTERN_MATCH(1) 비트가 켜져 있으면 arg1을 패턴으로 비교하고 arg1이 없으면 이름을 가리지 않는다. 꺼져 있으면 이름이 같은 것만 찾고 arg1이 없으면 빈 이름으로 찾는다. arg2와 flag의 다른 비트는 사용하지 않는다.
  • tuple_count는 SELECT 문을 실행하는 스키마 타입(CLASS, VCLASS, QUERY_SPEC, ATTRIBUTE, CLASS_ATTRIBUTE, DIRECT_SUPER_CLASS, PRIMARY_KEY, ATTR_WITH_SYNONYM, SCHEMAS)에서는 그 결과의 행 수이고 그 밖의 스키마 타입에서는 CAS가 센 수다. METHOD와 CLASS_METHOD는 메서드, METHOD_FILE은 메서드 파일, SUPERCLASS와 SUBCLASS는 클래스, TRIGGER는 트리거의 수다. CONSTRAINT는 인덱스와 유일 제약 조건에 든 속성의 수이고, IMPORTED_KEYS, EXPORTED_KEYS, CROSS_REFERENCE는 외래 키에 든 속성의 수다. CLASS_PRIVILEGE는 찾은 클래스마다 그 클래스에 가진 권한의 수를, ATTR_PRIVILEGE는 찾은 속성마다 그 클래스에 가진 권한의 수를 더한 것이다.
  • 결과의 행은 응답의 핸들 번호로 FETCH를 보내 가져온다. 스키마 타입마다 행을 쓰는 CAS 함수와 그 차이는 구조 fetch_rows의 비고에 적었다.
  • 스키마 타입 PRIMARY_KEY에서 클래스를 찾지 못했을 때, ATTR_WITH_SYNONYM에서 arg1이 없거나 동의어가 없을 때, ATTR_WITH_SYNONYM에서 결과 코드만 쓰고 핸들을 남겨 둔 때에는 핸들에 SELECT 문의 결과가 없다. 이 핸들로 FETCH를 보내면 CAS는 num_tuple 0으로 응답하지 않고 오류로 응답한다. 오류 코드는 CAS_ER_NO_MORE_DATA이고, PRIMARY_KEY의 핸들에 result_set_index를 1 이상으로 보냈을 때는 CAS_ER_NO_MORE_RESULT_SET이다.
  • CAS에는 스키마 타입을 클라이언트의 프로토콜 버전으로 가리는 조건이 없다. 스키마 타입 SCHEMAS도 클라이언트의 버전과 상관없이 처리한다.
  • cas_shard_flag가 켜진 CAS는 핸들 수가 MAX_PREPARED_STMT_COUNT에 이르러도 CAS_ER_MAX_PREPARED_STMT_COUNT_EXCEEDED 오류로 응답하지 않는다.
  • JDBC의 UConnection.getSchemaInfo는 연결이 닫혀 있으면 ER_IS_CLOSED, 스키마 타입이 1보다 작거나 21보다 크면 ER_SCHEMA_TYPE, flag가 0보다 작거나 3보다 크면 ER_ILLEGAL_FLAG 오류로 끝내고 요청을 보내지 않는다. 보낼 때는 arg1이나 arg2가 null이면 길이 0인 인자로 싣고 shard_id를 항상 싣는다. 응답에서는 결과 코드를 핸들 번호로 읽고 이어서 tuple_count, num_column, columns를 읽는다.
  • JDBC는 CUBRIDDatabaseMetaData의 메서드에서만 이 요청을 보낸다. getTables는 스키마 타입 CLASS를, getTablePrivileges는 CLASS_PRIVILEGE를, getPrimaryKeys는 PRIMARY_KEY를, getSuperTables는 DIRECT_SUPER_CLASS를 flag 3으로 보낸다. getColumnPrivileges는 ATTR_PRIVILEGE를, getIndexInfo는 CONSTRAINT를 flag 2로 보낸다. getBestRowIdentifier는 CONSTRAINT를 flag 2로 보내고, 그 결과에서 사용할 제약 조건을 찾았으면 ATTRIBUTE를 flag 2로 한 번 더 보낸다. getImportedKeys, getExportedKeys, getCrossReference는 IMPORTED_KEYS, EXPORTED_KEYS, CROSS_REFERENCE를 flag 3으로 보내고, 넘겨받은 테이블 이름이 null이면 요청을 보내지 않고 예외를 던진다.
  • JDBC의 CUBRIDDatabaseMetaData.getColumns는 스키마 타입 ATTRIBUTE를 보낸다. 테이블 이름 패턴이 null이거나 %나 _를 포함하면 flag의 CCI_CLASS_NAME_PATTERN_MATCH(1) 비트를, 컬럼 이름 패턴이 null이거나 %나 _를 포함하면 CCI_ATTR_NAME_PATTERN_MATCH(2) 비트를 켠다.
  • JDBC의 CUBRIDDatabaseMetaData.getSchemas(String, String)는 CUBRID에 연결되어 있고 서버의 프로토콜 버전이 V13 이상일 때만 스키마 타입 SCHEMAS를 flag 1로 보낸다. 그렇지 않으면 요청을 보내지 않고 빈 결과를 돌려준다.
  • JDBC는 스키마 타입 VCLASS, QUERY_SPEC, CLASS_ATTRIBUTE, METHOD, CLASS_METHOD, METHOD_FILE, SUPERCLASS, SUBCLASS, TRIGGER, ATTR_WITH_SYNONYM을 보내지 않는다. JDBC의 USchType에는 ATTR_WITH_SYNONYM(20)의 상수가 없다.
