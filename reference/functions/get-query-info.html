GET_QUERY_INFO

핸들이 실행한 질의나 주어진 SQL 문의 실행 계획 문자열을 돌려준다

항목내용
함수 코드24
엔진 이름CAS_FC_GET_QUERY_INFO
JDBC 이름GET_QUERY_INFO
대조한 커밋엔진 e30370dc03, JDBC 18d5254624 (2026-11-14)

요청​

순서필드형식크기조건설명
1srv_h_idARG_INT8서버 핸들 번호다. sql_stmt가 오면 CAS가 이 값을 사용하지 않고 새 핸들을 만든다
2info_typeARG_BYTE5가져올 정보의 종류다. CAS는 CAS_GET_QUERY_INFO_PLAN(1)일 때만 계획을 돌려주고 JDBC는 항상 1을 보낸다
3sql_stmtARG_STRING4 + n인자가 3개 이상일 때계획을 볼 SQL 문이다. 길이가 0 이하이면 없는 것으로 다룬다

응답​

결과 코드: 성공하면 0

순서필드형식크기조건설명
1query_planBYTES가변계획 문자열이고 NUL 바이트로 끝나며 길이 필드가 없다. 본문 끝까지가 이 문자열이다

비고​

  • 인자가 2개보다 적으면 CAS는 CAS_ER_ARGS 오류로 응답한다. CAS는 인자를 셋만 읽고 네 번째부터는 읽지 않는다.
  • sql_stmt가 있으면 CAS는 새 핸들을 만들어 그 SQL 문을 열고 컴파일하고 실행한 뒤 그 핸들의 계획을 읽고 핸들을 지운다. 컴파일이나 실행이 실패하면 DBMS 오류로 응답한다. 실행 오류 가운데 바인드 값이 모자란다는 오류는 무시한다.
  • sql_stmt가 없으면 CAS는 srv_h_id 핸들의 계획을 읽는다. 핸들이 없으면 CAS_ER_SRV_HANDLE 오류로 응답한다.
  • query_plan은 핸들이 질의 정보를 모으도록 표시되어 있고 info_type이 1일 때만 값이 있다. 그렇지 않거나 계획 파일을 열지 못하면 NUL 한 바이트만 쓴다. 계획 파일의 내용은 읽은 그대로 이어 붙인다.
  • 핸들은 PREPARE의 flag에 CCI_PREPARE_QUERY_INFO가 있었거나 EXECUTE의 flag에 CCI_EXEC_QUERY_INFO가 있을 때 질의 정보를 모으도록 표시된다. CCI_EXEC_QUERY_ALL로 실행하거나 CALL 플래그로 준비한 핸들을 실행하면 표시가 지워진다. sql_stmt로 만든 새 핸들은 CAS가 표시한다.
  • sql_stmt가 있고 새 핸들을 만들지 못하면 CAS는 결과 코드 없이 NUL 한 바이트만 응답 본문으로 쓴다. 핸들 수가 브로커 파라미터 MAX_PREPARED_STMT_COUNT에 이르렀을 때와 메모리가 모자랄 때가 그렇다. 이 경로는 본문의 첫 4바이트가 결과 코드라는 규칙이 맞지 않는다. JDBC는 본문 크기가 4바이트보다 작아 결과 코드를 읽지 못하고 ER_ILLEGAL_DATA_SIZE 오류로 다룬다.
  • cas_shard_flag가 켜진 CAS는 핸들 수가 MAX_PREPARED_STMT_COUNT에 이르러도 새 핸들을 만든다.
  • JDBC는 UStatement.getQueryplan에서 핸들 번호와 info_type만 보내고, UConnection.getQueryplanOnly에서 srv_h_id 0과 SQL 문을 함께 보낸다. 두 메서드 모두 결과 코드 뒤의 남은 본문 전체를 문자열로 읽고 마지막 NUL을 뗀다.

버전별 차이​

버전에 따라 생기거나 없어지는 필드가 없다.
