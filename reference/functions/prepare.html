PREPARE

SQL 문을 준비하고 서버 핸들과 문장 정보를 돌려준다

항목내용
함수 코드2
엔진 이름CAS_FC_PREPARE
JDBC 이름PREPARE
대조한 커밋엔진 e30370dc03, JDBC 18d5254624 (2026-11-14)

요청​

순서필드형식크기조건설명
1sql_stmtARG_STRING4 + n준비할 SQL 문
2flagARG_BYTE5플래그: PREPARE 플래그
3auto_commit_modeARG_BYTE5인자가 3개 이상일 때1이면 자동 커밋 모드다. JDBC는 항상 보낸다
4deferred_close_handleARG_INT × 0..*가변닫을 서버 핸들 번호다. 인자의 끝까지 반복하고, JDBC가 미뤄 둔 핸들 닫기를 이 요청에 실어 보낸다

응답​

결과 코드: 성공하면 새 서버 핸들의 번호

순서필드형식크기조건설명
1result_cache_lifetimeINT4클라이언트가 결과를 캐시해 둘 수 있는 기간이다. 음수이면 캐시하지 않는다
2stmt_typeBYTE1문장 종류다. CALL 플래그로 준비하면 CUBRID_STMT_CALL_SP다. 값: 문장 종류, 문장 종류의 특수 값
3num_markersINT4바인드 위치 표시자의 수다
4column_listprepare_column_list_info가변
4.1updatable_flagBYTE1결과를 갱신할 수 있으면 1, 아니면 0이다. JDBC는 1일 때만 갱신 가능으로 읽는다
4.2num_columnINT4결과 컬럼의 수다
4.3columnsprepare_column_info × num_column가변

비고​

  • 인자가 2개보다 적으면 CAS는 CAS_ER_ARGS 오류로 응답한다.
  • auto_commit_mode 뒤의 인자는 모두 닫을 핸들 번호로 읽는다. CAS는 각 번호의 서버 핸들을 해제한다.
  • CAS는 닫을 핸들을 해제하고 flag를 검사한 뒤 새 서버 핸들을 만든다. 핸들 수가 브로커 파라미터 MAX_PREPARED_STMT_COUNT에 이르렀으면 CAS_ER_MAX_PREPARED_STMT_COUNT_EXCEEDED 오류로, 메모리가 모자라면 CAS_ER_NO_MORE_MEMORY 오류로 응답한다.
  • flag에 CCI_PREPARE_UPDATABLE과 CCI_PREPARE_HOLDABLE이 함께 있으면 CAS는 CAS_ER_HOLDABLE_NOT_ALLOWED 오류로 응답한다. CCI_PREPARE_UPDATABLE이 있으면 CAS는 CCI_PREPARE_INCLUDE_OID도 켠다.
  • result_cache_lifetime은 SELECT가 아니거나, CAS가 데이터베이스에 접속할 때 읽어 둔 기본 격리 수준이 REPEATABLE READ나 SERIALIZABLE이거나, 브로커의 JDBC 결과 캐시가 꺼져 있거나, 힌트가 있어야만 캐시하도록 설정했는데 힌트가 없으면 -1이다.
  • 문장을 컴파일하지 못한 오류가 ER_PT_SEMANTIC이고 문장이 INSERT, UPDATE, DELETE, MERGE, 메서드 호출, EVALUATE 문이며 바인드 값이 있어야 컴파일되는 경우이면 CAS는 오류로 응답하지 않고 준비를 끝낸다. 이때 stmt_type은 파서가 정한 문장 종류로, num_markers는 다른 경우와 같이 SQL 문에서 세어 채우고 컬럼 정보는 구조 prepare_column_list_info의 비고에 적은 규칙대로 쓴다.
  • 질의 대체 규칙이 맞으면 CAS는 대체한 질의를 준비하고, num_markers에는 원래 질의의 표시자 수를 쓴다. 대체한 질의를 준비하지 못하면 원래 질의를 다시 준비해 응답한다.
  • 준비가 오류로 끝나면 auto_commit_mode가 1일 때 CAS는 응답을 보내기 전에 롤백한다.
  • cas_shard_flag가 켜진 CAS는 deferred_close_handle을 읽지 않는다. 핸들 수가 MAX_PREPARED_STMT_COUNT에 이르러도 CAS_ER_MAX_PREPARED_STMT_COUNT_EXCEEDED 오류로 응답하지 않는다. 요청의 CAS 정보 additional_flag에 FORCE_OUT_TRAN 비트가 켜져 있으면 응답을 만든 뒤 보내기 전에 롤백한다.
  • JDBC는 문장 종류가 CALL_SP이면 응답의 컬럼 수대로 컬럼 정보를 읽은 뒤 컬럼 수를 num_markers + 1로 다시 정한다.

버전별 차이​

버전에 따라 생기거나 없어지는 필드가 없다.
