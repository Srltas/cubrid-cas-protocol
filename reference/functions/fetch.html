FETCH

핸들의 결과에서 지정한 위치부터 행 묶음을 가져온다

항목내용
함수 코드8
엔진 이름CAS_FC_FETCH
JDBC 이름FETCH
대조한 커밋엔진 e30370dc03, JDBC 18d5254624 (2026-11-14)

요청​

순서필드형식크기조건설명
1srv_h_idARG_INT8행을 가져올 서버 핸들 번호다
2cursor_posARG_INT8가져올 첫 행의 위치이고 1부터 센다
3fetch_countARG_INT8가져올 행 수다. 0 이하이면 CAS가 100으로 바꾼다
4fetch_flagARG_BYTE5CCI_FETCH_SENSITIVE(0x01) 비트가 켜져 있으면 갱신 가능한 컬럼을 객체에서 다시 읽는다. JDBC는 결과가 sensitive이면 1, 아니면 0을 보낸다
5result_set_indexARG_INT8결과 번호이고 1부터 센다. 0 이하이면 현재 결과를 사용한다

응답​

결과 코드: 성공하면 0

순서필드형식크기조건설명
1rowsfetch_rows가변행 묶음이다. 이 내용을 쓰는 CAS 함수는 핸들 종류마다 다르고 구조 fetch_rows의 비고에 적었다
1.1num_tupleINT4이 응답에 실은 행의 수다
1.2fetched묶음가변스키마 타입 ATTRIBUTE, CLASS_ATTRIBUTE, ATTR_WITH_SYNONYM의 핸들에서 요청한 위치가 결과의 끝을 넘은 경우가 아닐 때
1.2.1tuples묶음 × num_tuple가변
1.2.1.1cursor_positionINT4행의 위치이고 1부터 센다
1.2.1.2oidobject_id8행의 객체 식별자다. 결과가 객체 식별자를 포함하지 않으면 세 필드가 모두 0이다
1.2.1.3valuesVALUE × 0..*가변행의 컬럼 값이다. 컬럼 수만큼 이어지며 컬럼 수와 값의 타입 코드는 이 구조 안에 없고 그 핸들의 컬럼 정보에서 얻는다
1.2.2fetch_end_flagBYTE1결과의 마지막 행까지 보냈으면 1, 아니면 0이다. EXECUTE의 max_row에서 멈출 때는 0이다

비고​

  • 인자가 5개보다 적으면 CAS는 CAS_ER_ARGS 오류로 응답한다. 서버 핸들이 없으면 CAS_ER_SRV_HANDLE 오류로 응답한다. CAS는 인자를 다섯만 읽고 여섯 번째부터는 읽지 않는다.
  • 행을 쓰는 CAS 함수는 핸들로 정해진다. 저장 프로시저 호출(CALL 플래그)로 준비한 핸들은 fetch_call이 쓴다. 이때 cursor_pos, fetch_count, fetch_flag, result_set_index는 사용하지 않는다. 그 밖에는 핸들의 스키마 타입으로 정한다. 질의 결과 핸들은 CAS 함수 fetch_result가 쓰고, 스키마 정보 핸들은 스키마 타입마다 다른 함수가 쓴다. 스키마 타입이 범위를 벗어나면 CAS_ER_SCHEMA_TYPE 오류로 응답한다.
  • CAS 함수 fetch_result는 질의 결과와 스키마 타입 CLASS, VCLASS, QUERY_SPEC, DIRECT_SUPER_CLASS, PRIMARY_KEY, SCHEMAS의 핸들을 처리한다. 모든 함수가 같은 필드를 같은 순서로 쓰고, 다른 점은 구조 fetch_rows의 비고에 적었다.
  • result_set_index는 CAS 함수 fetch_result만 읽는다. 양수이면 그 번째 결과를 읽고, 핸들이 지금 읽고 있는 결과의 번호보다 크면 CAS_ER_NO_MORE_RESULT_SET 오류로 응답한다. 결과가 없거나 문장이 결과 집합을 돌려주는 종류가 아니면 CAS_ER_NO_MORE_DATA 오류로 응답한다.
  • fetch_flag는 CAS 함수 fetch_result만 읽는다. CAS는 결과에 갱신 가능한 컬럼 정보가 있을 때만 이 비트를 따라 db_synchronize_cache를 부른 뒤 갱신 가능한 컬럼을 행의 객체에서 다시 읽는다. 행의 객체가 없으면 그 컬럼은 값이 없는 것(NULL)이다.
  • fetch_count는 fetch_attribute, fetch_method, fetch_methfile, fetch_class, fetch_trigger, fetch_privilege만 따른다. CAS 함수 fetch_result는 이 값을 보지 않고 응답의 크기가 브로커 파라미터 NET_BUF_SIZE 이상이 되거나 결과의 끝이나 max_row에 닿을 때까지 싣는다. JDBC는 fetchSize를 보낸다.
  • CAS 함수 fetch_result와 fetch_call이 응답을 보내기 전에 커밋하는 조건은 구조 fetch_rows의 비고에 적었다.
  • 스키마 타입 ATTRIBUTE, CLASS_ATTRIBUTE, ATTR_WITH_SYNONYM의 핸들에서 요청한 위치가 결과의 끝을 넘으면 응답은 결과 코드와 num_tuple 4바이트로 끝난다(구조 fetch_rows의 fetched). JDBC는 FETCH 응답에서 fetch_end_flag를 항상 읽으므로 이 응답을 받으면 ER_ILLEGAL_DATA_SIZE 오류를 낸다.
  • cas_shard_flag가 켜진 CAS는 CAS 함수 fetch_result가 행을 싣는 응답 크기의 한도가 NET_BUF_SIZE가 아니라 512KB이고, 오류일 때 자동 커밋 모드의 앞으로만 가는 핸들을 자동 롤백으로 표시한다.
  • JDBC는 가져오기 방향이 FETCH_REVERSE이면 cursor_pos를 현재 위치 - fetchSize + 2로 보내고 1보다 작으면 1을 보낸다. 그 밖의 방향이면 현재 위치 + 1을 보낸다. result_set_index는 항상 0을 보낸다. JDBC는 EXECUTE 응답에 붙은 첫 행 묶음을 EXECUTE 응답의 일부로 읽고 FETCH 요청은 그 뒤의 행을 가져올 때 보낸다.

버전별 차이​

버전에 따라 생기거나 없어지는 필드가 없다.
