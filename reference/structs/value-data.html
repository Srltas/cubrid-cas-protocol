비고​

  • 이 구조는 VALUE나 ARG_VALUE의 길이 필드 뒤에 오는 내용만 가리킨다. 응답에서 값이 없는 것(NULL)은 길이가 -1이고 내용이 없다. 응답의 길이 0은 NULL이 아니라 내용이 빈 값이다(비트 수가 0인 BIT, VARBIT). 요청의 값 인자와 요청의 컬렉션 안 원소는 길이가 0 이하이면 NULL이다.
  • 내용의 타입 코드는 이 구조 안에서 정해지지 않는다. 응답은 컬럼 정보의 타입 코드(type_info가 있으면 그 코드)로, 요청은 바인드 값의 타입 인자(bind_value)나 컬렉션의 원소 타입으로 정해진다. 아래 묶음은 타입 코드마다 하나씩이고 코드 값이 작은 것부터 놓았다.
  • NULL(0), NCHAR(3), VARNCHAR(4), USHORT(26), UINT(27), UBIGINT(28), TIMETZ(33)에는 묶음이 없다. NULL은 길이만 있고 내용이 없다. 나머지 타입 코드는 CAS가 응답에 쓰지 않고, 요청으로 오면 CAS_ER_UNKNOWN_U_TYPE 오류로 거절한다. JDBC에는 NCHAR, VARNCHAR, USHORT, UINT, UBIGINT 값을 싣고 읽는 코드가 있다.
  • JDBC는 문장이 CALL, EVALUATE, CALL_SP이거나 컬럼 정보의 타입 코드가 NULL일 때 값의 타입과 상관없이 type_info를 먼저 읽는다. CAS는 그 조건에서도 JSON 값에는 type_info를 붙이지 않으므로, 이때 JDBC는 JSON 문자열의 앞 바이트를 type_info로 읽는다. GET_STATS 문장은 JDBC의 조건에 없지만, CAS가 CALL, GET_STATS, EVALUATE 문장의 결과 컬럼을 타입 코드 NULL로 알리므로 JDBC는 컬럼의 타입 코드 조건으로 type_info를 읽는다.
  • type_info의 길이는 값의 길이에 포함된다. V7 이상의 클라이언트에는 항상 2바이트다.
  • type_info는 OID_GET의 values, COLLECTION의 elements, GET_GENERATED_KEYS의 values에는 붙지 않는다. OID_GET에서는 columns의 타입 코드가 NULL(0)인 속성의 값에도 붙지 않는다.
  • char, string, enum 묶음의 chars에서 길이는 값의 길이에서 앞의 type_info를 뺀 것이고 NUL을 포함한다.
  • bit와 varbit 묶음의 bytes는 응답에서 비트 수를 8로 올림한 바이트 수만큼 쓴다. CAS는 요청의 bytes를 바이트 수의 8배를 비트 수로 읽는다.
  • set_response, multiset_response, sequence_response 묶음의 elements에서 원소 타입이 서로 다르면 CAS는 컬렉션 전체를 값이 없는 것으로 보낸다.
  • set_request, multiset_request, sequence_request 묶음의 elements에서 원소의 길이가 남은 바이트보다 크면 CAS는 거기서 읽기를 멈춘다. 길이가 0 이하인 원소는 NULL이다.
  • timestamptz_request, timestampltz_request, datetimetz_request, datetimeltz_request 묶음에서 CAS는 timezone의 길이를 CCI_TZ_SIZE와 견주어 크면 CAS_ER_TYPE_CONVERSION 오류를 낸다.
  • timestamptz_response, timestampltz_response, datetimetz_response, datetimeltz_response 묶음에서 날짜와 시각은 timezone의 시간대로 바꾼 값이다. TIMESTAMPLTZ와 DATETIMELTZ에서는 그 시간대가 세션의 시간대다.
  • V7 클라이언트에는 CAS가 JSON 값의 컬럼 타입 코드를 STRING으로 알린다.
  • 요청의 object 묶음에서 CAS는 식별자로 객체를 얻지 못하거나 그 객체가 인스턴스가 아니면 오류로 응답하지 않고 값이 없는 것(NULL)으로 읽는다.
