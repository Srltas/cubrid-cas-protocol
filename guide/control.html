질의 취소와 상태 확인

드라이버가 연결을 맺은 뒤에 브로커 포트로 따로 보내는 요청을 설명한다. 이 요청은 모두 CAS가 아니라 브로커가 처리한다. 필드의 이름과 크기, 값은 각 메시지 페이지에 있다.

  • PING: 브로커가 응답하는지 확인한다
  • STATUS: CAS 하나의 함수 처리 상태를 묻는다
  • CANCEL: CAS에서 실행 중인 질의를 취소한다

세 요청은 브로커 포트에 새로 연 연결의 첫 요청으로 보낸다. CONNECT_BROKER 요청이 오는 자리와 같다. 브로커는 요청을 읽고, 접근 제어 목록이 켜져 있으면 가장 먼저 검사한 다음, 요청 앞의 문자로 어느 요청인지 구분한다. 브로커는 응답 하나를 보내고 연결을 닫는다.

질의 취소​

JDBC는 UStatement.cancel이 UConnection.cancel을 부르고, 이것이 브로커 포트에 새로 연결해서 CANCEL 요청을 보낸다. 질의를 실행하는 연결은 쓰지 않는다. 요청은 질의를 취소할 CAS의 프로세스 번호를 싣고, V13부터는 세션 ID도 싣는다. 둘 다 CONNECT_DB의 성공 응답으로 받은 값이다.

브로커는 서비스 중인 CAS 가운데 프로세스 번호가 같고 클라이언트에 배정된 CAS를 찾는다. 요청을 보낸 클라이언트의 IP가 그 CAS의 클라이언트 IP와 같아야 하고, 요청에 세션 ID가 있으면 CAS가 기록한 세션 ID와 같아야 한다. 그 CAS의 클라이언트가 V13 이상이면 세션 ID가 없는 요청은 받아들이지 않는다. 모두 맞으면 브로커가 그 CAS에 신호를 보내고 성공으로 응답한다. 브로커는 그 CAS가 질의를 실행하고 있는지는 확인하지 않고, 신호만 보낼 뿐 취소된 질의의 결과는 알려 주지 않는다. 맞는 CAS가 없으면 오류 코드로 응답한다.

요청은 형식이 둘이고 JDBC는 그 가운데 하나만 보낸다. 형식마다 성공일 때의 응답 값과 오류 코드를 옛 값으로 바꾸어 보내는 조건이 다르다. 자세한 것은 CANCEL에 있다.

상태 확인​

STATUS 요청은 CAS의 프로세스 번호와 세션 ID를 싣는다. 브로커는 서비스 중이고 프로세스 번호가 같은 CAS를 찾아 세션 ID까지 같으면 그 CAS의 함수 처리 상태를 응답하고, 맞는 CAS가 없거나 세션 ID가 다르면 상태가 없다는 값을 응답한다. 상태 값의 뜻은 STATUS에 있다.

JDBC는 두 곳에서 이 요청을 쓴다.

  • UConnection.isValid는 응답이 상태가 없다는 값이 아니면 연결이 유효하다고 본다. 요청을 보내거나 응답을 읽다가 예외가 나면 유효하지 않다고 본다.
  • 함수 응답을 기다리다가 소켓의 읽기 제한 시간이 지나면 이 요청을 보낸다. 응답이 처리 중이 아니면 한 번 더 기다리고, 두 번째에도 처리 중이 아니면 통신 오류로 처리한다.

브로커 응답 확인​

PING 요청은 브로커가 응답하는지만 확인한다. 브로커는 접근 제어 검사를 통과한 요청에 성공으로 응답한다. JDBC는 연결 과정의 응답을 기다리다가 소켓의 읽기 제한 시간이 지나면 브로커 포트에 새로 연결해서 PING을 보내고 응답을 읽는다. 응답이 오면 원래 소켓 읽기를 다시 시도하고, 전체 제한 시간이 남아 있는 동안 읽기 제한 시간이 지날 때마다 PING을 다시 보낸다. 연결하거나 읽지 못하면 예외가 나서 읽기가 실패한다.

응답이 없거나 거부되는 경우​

세 요청 모두 브로커가 멈춘 CAS가 기준보다 많다고 판단해 새 클라이언트를 거절하는 동안에는 요청을 읽지 않고 응답 없이 연결을 닫는다. 요청을 다 읽지 못해도 응답 없이 연결을 닫는다. 접근 제어 목록이 요청을 거부하면 오류 코드를 응답한다.
